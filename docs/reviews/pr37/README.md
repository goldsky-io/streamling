## Reproduce

Run from the repository root. The component suites use the existing Cargo dependencies. The full-binary e2e suites use the normal local infrastructure configured by `infra/local-k8s/env.sh` and isolate their topics/databases with TestContext. `RUST_LOG=info` is required by the print-sink assertions.

```sh
cargo build -p streamling --bin streamling --locked
source infra/local-k8s/env.sh
export E2E_STREAMLING_BIN="$PWD/target/debug/streamling"
export RUST_LOG=info
```

Execute each group even if earlier groups exit101. Drop `--offline` on a fresh checkout if dependencies are not cached. No companion checkout is required for the committed tests.

```sh
cargo test -p streamling-common --locked --offline --no-fail-fast \
  --test deep_v2_math_continuity \
  --test deep_v2_serialization \
  --test deep_v3_legacy_wire \
  --test deep_v3_math \
  --test deep_v3_parquet_options \
  --test deep_v3_plugin_contract \
  --test deep_v3_wire -- --nocapture --test-threads=2
```

The live ClickHouse provider tests are ignored by default because they require a running server. They create and remove uniquely named Memory tables; execute them explicitly:

```sh
cargo test -p streamling-connectors --test deep_v3_plugin_clickhouse --locked \
  -- --ignored --nocapture --test-threads=1
```

Their default endpoint is `http://127.0.0.1:30123`; override with `STREAMLING_REVIEW_CLICKHOUSE_URL`, `STREAMLING_REVIEW_CLICKHOUSE_DATABASE`, `STREAMLING_REVIEW_CLICKHOUSE_USER`, and `STREAMLING_REVIEW_CLICKHOUSE_PASSWORD` if needed. The I256 legacy case is explicitly a diagnostic without a current companion producer; the U256 case models a verified current source contract.

## Independent fixtures

The checked-in JSON oracles use exact Python Fraction arithmetic with deterministic seeds; Rust tests do not invoke Python. Regenerate them with:

```sh
python3 scripts/reviews/pr37/generate_math_oracle.py
python3 scripts/reviews/pr37/generate_pipeline_oracle.py
```

The small Parquet fixtures are self-contained and embedded by the Rust tests. Optional regeneration requires PyArrow21.0.0:

```sh
python3 scripts/reviews/pr37/generate_parquet_fixtures.py
```

All fourteen numerical JSON/Parquet assets regenerated byte-identically during review. The generators support output overrides (`STREAMLING_REVIEW_TEST_DIR`, `STREAMLING_REVIEW_PIPELINE_ORACLE`, `STREAMLING_REVIEW_PARQUET_FIXTURE_DIR`) for non-mutating comparisons.

## Validation interpretation

Full logs, SQL matrices, exact source probes, timestamps, fixture hashes, and preliminary failures are in the separately delivered evidence archive.

The existing raw e2e timeout helper does not kill a child on timeout. Investigate any future timeout before attributing it to numeric corruption; clean up only the affected test's process and UUID resources. No final numerical finding relies on an unexplained timeout.
